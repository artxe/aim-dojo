## Source of truth (don't restate in notes)

- `pool.js` — `create_pool(make)` free-list: `obtain`/`recycle`/`clear`
- `constants.js` — immutable tuning; imports only `math.js`. `fov.<game>` = declared FOV numbers + one `axis` + an `ads` map of the SELECTABLE ADS scopes where the game offers a choice; `sens.<game>` = engine curve coefficients + `decimals` (input grid). A per-game number belongs here, never hardcoded in a formula
- `math.js` — `calc_core_radius`, `clamp`, `convert_deg_across_aspect`, `lerp`, `normalize_rad`, `round_to`, `to_deg`/`to_rad`, `EPS`/`TAU` + re-exported `Math.*`; imports nothing
- `private.d.ts` — global types
- `bg_store.js` — IndexedDB for uploaded BG blobs (split `bg_videos` meta + `bg_blobs` stores; DB version = schema version, NOT app version). `state.bg.video_id` = record id; blobs never touch localStorage
- `sfx.js` — `get_audio_time()`, `play_shot/hit/miss()`, `set_audio_visible()`. Buffers render OFF the critical path (`sound_buffers` promise → `let crit_sound`/`hit_sound`/`miss_sound` in a `.then()`; `play_buffer` no-ops while unset). **No top-level await anywhere in `docs/js/`** — it blocks EVERY importer's evaluation (`main.js → window.js → sfx.js` once put the app behind three `OfflineAudioContext` renders). `new AudioContext()` stays sync at module load on purpose — `get_audio_time()` runs every frame, so deferring moves the cost into a run's first frame
- `component/select.js` — state-free light-DOM `x-select`: direct `button`/`ul`/`li[data-value]` markup, keyboard/focus/ARIA, native-like silent `.value`, user-only `change`, `selectaction`/`selectremove`. click-css styles the real child nodes
- `controller/dom.js` — all DOM refs + `send_toast`, `set_attr_if_changed`, `set_best_score`, `set_text_if_changed`
- `main.js` — startup wiring
- `docs/index.html` — markup + click-css style/class syntax, expanded at runtime by `docs/lib/click-css.min.js` (**v1.1.0** — the `<style click>` attribute carries the version). Three v1.1.0 rules bite silently, because a wrong abbreviation or a missing unit is still syntactically valid and just renders wrong: **`tr` is `transition`, `tt` is `text-transform`** (`tt` meant `transition` in v1.0.0 — an untouched `tt=.1s` compiles to `text-transform:.1s` and the animation just stops); **`line-height` is NOT auto-px'd** (write `lh=24px`; bare `lh=24` is a 24× unitless multiplier); **`calc()` operators need their own spaces** — write `calc(100%_-_4.5ch)`, v1.1.0 dropped the pass that inserted them. Escapes are `\_` (literal `_`) and `\=` (literal `=`); a `~` prefix on a value opts out of auto-px (`lh=~1.5`). Renames from v1.0.0: `mi`→`mx`, `pi`→`px`, `b{b,t}{l,r}r`→`br{b,t}{l,r}`; `at`/`cv`/`ji`/`pc`/`v` were dropped (spell those out). New: `mah`/`maw`/`mih`/`miw`, `my`/`py`
- `game_mode/<name>.js` — that mode's runtime AND persisted state, module-local: own `STORAGE_KEY = "<name>#best_score"`, `best_score`, score display, exported `clear_best_score()`. `state.js` knows nothing about modes

## Conventions
- Read `const { x } = state.foo`; write `state.foo.x = v` (review-enforced, not lint)
- Alphabetize within local groups: imports + named lists, object/type keys, fn defs, exported `dom.js` refs, independent consts, `else if` chains over string literals, order-insensitive assigns. Five rules make it decidable:
  - **imports sort on the FULL specifier**, not the basename — `"../constants.js"` < `"../controller/dom.js"` < `"../render/camera.js"`, and every `"../…"` before every `"./…"` (`.` < `/`). 0 violations repo-wide; basename sort is the rejected reading. Bare side-effect imports (`import "./menu.js"`) keep position — boot ORDER, not a binding list
  - **case-INSENSITIVE** — `abs, EPS, fround, round`; `cos, PI, sin, tan, TAU`
  - **numeric suffix sorts with its family** — `x1` → `x10` → `x2`; a trailing `_el`/`_input` never re-orders it: `al_x1_el, al_x10_el, al_x2_el`
  - **module-level declarations group then sort**: UPPER_SNAKE consts → lowercase consts → `let`s, each band sorted
  - **a semantic block is its own group**: each WebGL program in `renderer_3d.js` keeps its uniforms/VAOs beside it; a const forced early by a dependency (`scripts/fragment_bg.js:ROOT`) stays put
- `constants.fov.<game>` FOV fields use in-game scope names (`x1`, `operator2_5`, `awp2`), never a generic `ads` — the two `ads`/`ads_stage2` MAPS are the exception that proves it, since they hold no numbers of their own, only references to those named fields keyed by what the player picks. One `convert_deg_across_aspect` per value — fold chains by composing tan-ratios (4:3-horizontal → vertical is `(deg, 4, 3)`, not 4:3→16:9→vertical). No `render_*` intermediate consts
- **Bilingual prose, English chrome.** `i18n.js` exports ONE function, `lang_text(pair)` → `pair[state.lang]`, and `LangText` (`private.d.ts`) is `Record<LangName, string>`, i.e. `{ en, ko }`. Every player-facing PROSE string is a pair resolved at RENDER time: `tutorial.js` `text`/`keys` (`TutorialStep.text`/`keys` ARE `LangText`, resolved in `show_step()`, never at module load — that is what lets the language change without a reload) and every `send_toast` argument. Everything a player matches against a real game UI stays English and is NOT a pair: HUD labels (`Score/Peak`, `Accuracy`, `Critical`/`Targets`), settings section titles, card labels/field names (`Hipfire(110)`, `ADS Unit`, `While Aiming`), game and mode names, config filenames, the copyright block, `<meta>`, `aria-label`s. Adding a string means deciding which side it is on — do not "finish the translation" by sweeping the chrome, that is what makes a setting findable in the actual game. Four mechanical rules:
  - **The export is `lang_text`, not `t`** — `t` is a local time variable in `game_mode/flick.js` and `twitch.js`, so the short name is a `no-shadow` error the moment either file needs a string
  - **Auto-detect, then override.** `state.lang` = `localStorage.getItem("lang") || (navigator.language.startsWith("ko") ? "ko" : "en")`. Nothing is persisted until the user picks in `#setting-language`, because `component/select.js`'s `.value` setter is deliberately SILENT — `main.js`'s `lang_select.value = state.lang` fires no `change`, so an un-chosen language keeps following the browser on every visit instead of being frozen by the first page load
  - **No Korean webfont is bundled, on purpose.** `body` is `ff='Share_Tech_Mono',_'Malgun_Gothic',_'Apple_SD_Gothic_Neo',_sans-serif` — Latin renders in the 42 KB mono face, Hangul falls through to the OS. A subset covering the tour's syllables would be 150 KB+ against a total font budget of 42 KB + a 1.7 KB logo subset, so the fallback is the cheaper trade. Do not add one without deciding that explicitly
  - **`body` carries `word-spacing=-6`** (a Share Tech Mono correction) and it CRUSHES Hangul, so every Korean-carrying container resets it: `#tutorial-tip` and `#toast > p` both end in `word-spacing=normal`. **`ws=` is `white-space`** — the full `word-spacing=` is the only spelling that works. Korean also needs more leading: the tip runs `lh=32px`/`lh=26px`, not the Latin `28px`/`24px`. `<html lang="en">` stays; `lang="ko"` sits on `#tutorial-tip` and `#toast` alone, so the mixed page stays honest for font selection and screen readers without moving the document language out from under the English metadata
  - **Korean prose names a game the way its players do; the English chrome keeps the official name.** A card opens `PUBG: BATTLEGROUNDS —` in both languages, but the Korean body says 배그, 롤, 카스2 — and 검은사막/라이벌즈/로블록스/마인크래프트/레인보우 식스/발로란트/서든어택/에이펙스/오버워치/포트나이트, whose full names already ARE the familiar ones. The English body mirrors it (Apex, CS2, League, PUBG, Rainbow 6, Valorant). Two words are fixed the same way and were mixed until 2026-08: **크로스헤어**, never 조준선, because the setting is labelled `Crosshair`, and **추천 감도**, never 적정 감도, for the number a card prints — 적정 감도 survives only as "the sens that suits YOU", which the LoL card now spells 자신에게 맞는 감도
- **File shape is fixed: `import`s → module-level declarations → `function` declarations → `export default` → the bare `{ … }` init block, LAST.** The braces are there to set the module's boot wiring (listener registrations, one-time DOM writes) apart from everything else, so it goes at the very bottom — below the default export too — and reads as the one thing that RUNS when the module is evaluated; hoisting is what lets it call functions written above it. `main.js` is nothing but imports + that block. The default export is otherwise the last thing in the file even when it is the module's main payload: `state.js` carried its state tree in the middle, above `create_queue`/`read_ads_scope`, and was the one file out of ten that read differently (2026-08; the 14 init blocks moved down in the same pass)
- Comments = JSDoc + narrow ESLint directives only; no prose comments
- Type cast: `/** @type {T} */(x)/**/` — trailing `/**/` required for parser stability
- **Every named type is a GLOBAL in `private.d.ts` — no `@typedef` in `.js`.** It is ambient: no import, no `import("./x.js").T`. JSDoc ANNOTATES (`@type`/`@param`/`@returns`), never declares. Only exception: `@template` on a generic fn (`create_pool`, `create_queue`). Classes stay classes (`component/select.js:XSelectElement`)
- JSDoc mirroring a declaration uses `typeof` on the source (`/** @type {typeof state.stats.shoots} */`) — never re-spell the shape
- Arrow fns only for one-off/disposable use (thin arg-forwarding wrappers). Reused/named/hot-path MUST use `function`
- **Bug-zero code**: no defensive error handling, logging, or watchdog instrumentation — native traces are the only debugging. Allowed `throw`s: dev-guards on unreachable branches (`else { throw Error(fn) }`) and genuine feature logic (`QuotaExceededError`, `try/finally`). No reactive error handlers (`onerror`, `"error"` listeners)
- **State-free import closure** (lint-enforced): `eslint.config.js:state_free_files` = modules whose import chain never reaches `state.js` (localStorage ⇒ browser-only). Each may import ONLY from that set; `calc_sens.js` and both `worker/*_worker.js` have stricter per-file allow-lists. Register a new state-free module there before any state-free file imports it
- **Optimization** must improve runtime perf — never trade perf for it, never reshape documented core APIs (`create_queue`). Add hot-path machinery (pools) only when O(1) ultra-light AND it removes a real per-frame allocation; skip where bookkeeping costs more or breaks correctness (`writing.lines` is consumed raw via `.array`, so flattened but NOT pooled)

## Camera derivation (the most-broken invariant — read before touching fov/sens)
```
update_camera_view()        picks the VIEW      → writes dimension, dist, fov_axis, sens_scale, view_fov → calls ↓
update_camera_projection()  owns ASPECT         → vfov → fov → sens → sens_error → rad_size
```
- Per-`sens` branches assign only LOCALS: `ads_fov`/`fov_axis`/`view_fov`, plus `dimension`/`dist`/`sens_scale` when they differ from the defaults. The shared tail writes them once. `dist`: branches assign the RAW `constants.tpp.<game>`, tail scales by `render_dist_scale`
- **`ads_fov` is the ADS FIELD's fov and `0` MEANS hipfire — what the player TYPED against, which is not always what the run SHOWS.** A branch with a scope choice writes `ads_fov = mb_right ? ads[scope] : 0` and `view_fov = mb_right ? ads[scope] : hipfire`; the tail hands `ads_fov` to `calc_sens_snap`, so the field chain the snap models is always a field the card actually printed. The three games whose ADS field is SHARED across scopes (`cs2`/`rb`/`val`) put `ads_ref[scope]` in `ads_fov` and leave `view_fov` on `ads[scope]` — the gap between the two IS the game's own per-weapon error and rides on `sens_scale`, exactly as a second zoom stage does. Games with no choice (`bdo`/`lol`/`mc`/`sa`) leave it `0` — their `calc_sens_snap` branch ignores it anyway
- Projection is the SECOND exported entry point and the one `on_resize()` uses alone. It re-derives everything from the CURRENT `width`/`height`, so **`vfov` is never carried across an aspect change**, and it leaves `dimension`/`dist` untouched so the `flick_180`/`aim_booster`/`writing` overrides survive. Order is load-bearing:
  - `vfov = convert_deg_across_aspect(calc_real_hfov(fov_axis, view_fov, width, height), width, height)`
  - `fov = convert_deg_across_aspect(vfov, height, width)` — round-trips a locked-horizontal view to EXACTLY its declared number
  - `sens = calc_camera_sens(fov) * sens_scale` — `render/camera.js`, plain `calc_rad_per_px(fov, width)` except `bdo`/`sa`, which ignore the arg and lock to hipfire fov (neither game zoom-corrects sens)
  - `rad_size = px_to_rad(constants.impact.px_size)` — needs the already-scaled `dist`
- **Storing `vfov` instead of `fov_axis`/`view_fov` was the pre-2026-08 shape and a real bug.** `start_game()` computes the view while the canvas is still WINDOWED size; the fullscreen `resize` landing a moment later re-derived `fov` from a vfov built at the browser-window aspect — VALORANT read **93.36° instead of 103°, sens 12.79 % slow**, on the very first run, and every `h`/`43` game drifted on any resize

## Non-obvious invariants
- **Start requires pointer lock + fullscreen.** `start_game()` keeps both `await`s, `.init()` and the first rAF in ONE `try`, so any rejection (e.g. the ~1.25 s pointer-lock cooldown right after an Escape release) aborts the whole call: `catch` exits lock/fullscreen and resets `state.game.mode = null` without ever starting a frame loop. Do not make it lock-optional. Module-level `starting` flag drops re-entrant calls. Losing lock in-game → auto `stop_game()`
- **THE AXIS A GAME DECLARES ITS FOV IN IS THE AXIS THAT STAYS FIXED WHEN THE ASPECT CHANGES.** No uniform Hor+/Vert− answer — it is per FOV VALUE, and `ow` uses both at once.

  | group | games | locked | on 21:9 |
  |---|---|---|---|
  | horizontal @16:9 (`"h"`) | `fn`, `ow` hipfire, `pubg`, `val` | horizontal, at EVERY aspect | **no** side bonus, vertical shrinks |
  | vertical (`"v"`) | `bdo`, `lol`, `mc`, `r6`, `rb`, `ow` scopes | vertical | side bonus |
  | horizontal @4:3 (`"43"`) | `al`, `cs2`, `sa` | **CROSSOVER at 4:3** — vertical above, horizontal below | side bonus |

  **Policy is DATA, not code**: `constants.fov.<game>.axis` is one `FovAxis` per game; every fov field is a number **as the game declares it**, NOT always vertical. An axis governs exactly the object it sits in — `ow` is the sole mixed game, its per-hero scopes nesting under `scopes: { axis: "v", ashe, emre, freja, widow }` apart from the `"h"` hipfire. `rb` nests for a different reason: `rivals: { exogun, hipfire, minigun, pistol, rifle, shotgun, slingshot }` are the weapon FOVs of **Rivals, a shooter INSIDE Roblox — not Marvel Rivals** (nothing in this repo touches that game; the misreading has already shipped one wrong tutorial line), while the bare `base` (120) is Roblox's own FOV slider — so `rb`'s "hipfire" is not the rendered hipfire view (that is `base`). The six weapon keys are **FOV GROUPS, not single guns** — Rivals quantizes to 5° (`45` Assault/Burst/Sniper Rifle, Crossbow, Gunblade, RPG, Energy Rifle · `60` Flare Gun, Handgun, Shorty, Spray · `75` Exogun, Freeze Ray · `90` Energy Pistols, Shotgun · `105` Slingshot) with the Minigun the one off-grid value at `112.5`. No `render[]` array; branches name fields (`hipfire`/`x1`/`widow`/`zoom`/…), so a view is picked by NAME, never index.
- **The ADS scope a run zooms to is per-game USER STATE, not a constant.** `constants.fov.<game>.ads` is the option map for the eight games that offer a choice (`al`, `cs2`, `fn`, `ow`, `pubg`, `r6`, `rb`, `val`); `state.game.ads_scope.<game>` is the chosen KEY, typed `keyof typeof constants.fov.<game>.ads`, persisted at `game.ads_scope.<game>`. `bdo`/`sa` (one forced chain) and `lol`/`mc` (no zoom) have no `ads` and no selector. The keys reuse the card's own field names (`al.ads.x4`, `ow.ads.ashe`, `fn.ads` = `{ scoped15, scoped40, targeting65, targeting80 }`), and each value REFERENCES the same IIFE local the card field does, so a FOV number is still written once. `state.js:read_ads_scope(ads, key, fallback)` reads localStorage and falls back when the stored key is not `in` the map — the one place a renamed option can't strand an existing user on an `undefined` FOV.
  - **The selector is trainer-only — it never moves a number on a card.** Cards that list a value PER scope (`al`/`fn`/`ow`/`pubg`/`r6`) already print the row the player types; the three shared-field games print the ONE row their game lets them type — `cs2`'s `AWP`, `val`'s `Scoped`/`ADS`, `rb`'s `While Aiming`/`While Scoped` — pinned to `ads_ref`, so those do not move either. `update_game_sens()` reads no `ads_scope` at all; the eight `on_change_*_ads_scope` handlers still call it, uniformly and for free. Per-weapon rows stay `_exact` reference readouts. Rivals' two cells DID follow the selector, from 2026-08 until the shared-field model landed
  - **An option is a WEAPON where the game's own field is per-weapon, and a MAGNIFICATION where the field is per-magnification.** `cs2`/`rb`/`val` are gun lists, `ow` is a hero list, `fn` is its two field names at two zooms each (`Targeting` → `ADS(80)` = the hipfire FOV + `ADS(65)`, `Scope` → `Scoped(40)` + `Scoped(15)`), and `al`/`pubg`/`r6` stay magnifications because those games really do give every scope its own sensitivity box. CS2's list was `aug`/`x1`/`auto2`/`awp2` for one day in 2026-08 — a mix of a gun and three zoom STAGES, and `x1` named nothing a player can pick up. It is now `aug`/`auto`/`awp`
  - **A SHARED ADS field is DATA: `constants.fov.<game>.ads_ref`, same keys as `ads`, each value the fov that ONE typed field is matched at.** Three games have one, because the game hands every scope the same box: `cs2` (one `zoom_sensitivity_ratio`, matched at the AWP's first stage, 40), `val` (TWO boxes — `ADS` matched at the Vandal's x1.25, `Scoped` at the Operator's x2.5 — so its map splits the gun list between them) and `rb` (`While Aiming`/`While Scoped`, both matched at the 45° Assault Rifle/Sniper Rifle, Rivals' meta pair — a reference that decides only two rows @16:9, where the 5 % grid parks 45/60/75/90 all on **120 %** and only the Slingshot 110 and the Minigun 105 move. How far the six spread is an ASPECT fact — @21:9 150/150/140/125/110/105, @5:4 90/95/95/100/100/100 — while resolution only nudges one row across a step (@4K/16:9 the Shotgun drops to 115)). Every OTHER scope then inherits that field's error instead of a matched sens, and that is the point — @FHD `val` Guardian **+4.58 %**, Marshal **+3.47 %**, Spectre **−1.96 %**; `cs2` AUG **−1.24 %**; `rb` Minigun **+13.73 %**, Slingshot **+8.77 %**. `al`/`ow`/`pubg`/`r6` have NO `ads_ref` — those games really do give every scope its own box — and `fn` has none because Zoom Scaling Standard pins both of its zoom fields at 100 %, so its error already falls out of the hipfire snap
  - **A second zoom stage is DATA: `constants.fov.<game>.ads_stage2`, same keys as `ads`, `0` = single stage.** Two games have one — `cs2` (AWP 40 → 10, Automatic/SSG08 40 → 15; the AUG stops at 45) and `val` (Operator x2.5 → x5). `logic.js:ads_stage_count()` is the ONE reader that has to answer "2 or 3" without a view update, and `window.js:cycle_ads_stage()` is its only caller; `sa` stays hardcoded at 3 there because its stages carry forced engine multipliers rather than a second selectable FOV. **Reaching stage 2 still needs `is_ads_cycled()`** — `game.ads_toggle` on — because a hold has no way to express a second stage
  - At stage 2 the branch just moves `view_fov` to `stage2`; ONE expression at the end of the branch covers it and the shared field alike — `sens_scale = calc_sens_<game>(ads_fov) / calc_sens_<game>(view_fov)` whenever the two differ (`rb` scales each side by its own fov first, because Rivals' aiming percent is ALREADY linearly fov-scaled). A second stage and a scope the field was not matched to are the same gap, so do not re-split them. Both games hand the player ONE typed field for both stages, so the second one genuinely overshoots — @FHD **`val` Operator +5.57 %, `cs2` AWP +3.75 %, `cs2` Automatic +3.41 %** — and the HUD's sens line says so. `calc_sens_snap` still runs the STAGE-1 chain: the typed field did not change, only the view did. This is `sa`'s `x5_sens`/`x15_sens` pattern — a stage multiplier applied in `logic.js`, never folded into the snap
- **`calc/calc_sens.js:calc_real_hfov(axis, fov_deg, width, height)` is the ONE implementation of those rules** — declared fov → true horizontal at this aspect. Every `calc_sens_*` delegates with its own `constants.fov.<game>.axis`; `controller/game_sens.js` calls it directly for `ow`'s vertical scopes (`ow.scopes.axis`, since one function can't cover a mixed game); `update_camera_projection()` derives the vertical by feeding its result straight back out. Keep it ONE function, ONE direction: a split inverted version needed `min` on one side and `max` on the other and silently shrank `cs2` to 86.30° at 5:4 instead of holding 90°. Only duplicate: `render/camera.js:calc_camera_sens`'s `bdo`/`sa` hipfire locks re-derive it inline — change a rule and they must follow. Verified 5:4/4:3/16:9/21:9 (`cs2` 90.00/90.00/106.26/121.66, `ow` widow 37.04/39.32/50.94/65.25, `twitch` spawn spread and the HUD follow for free)
- `constants.tpp.<game>` is renderer-orbit-only and never enters a sens formula — sens is view-independent (`calc/CLAUDE.md`). `fn` is the one game with TWO of them: Fortnite's ADS pulls the third-person camera IN rather than switching to first person, so `tpp.fn` (3) is hipfire, `tpp.fn_ads` (1) is either `targeting*` view, and only `scoped*` renders fpp
- `state.input.key_space` 30 fps cap SKIPS the rAF body and re-queues; it does not throttle rendering inside the frame
- **ONE clock: `state.timer.now_ms` (rAF). `now_s` is GONE — do not bring it back.** It held `AudioContext.currentTime` until 2026-08, yet nothing audio-critical read it (`sfx.js` schedules off its own `get_audio_time()`); its only consumers were impact fade, impact expiry and the tracking impact interval — pure visual timing on the coarsest clock in the browser. It advances one RENDER QUANTUM at a time — measured @48 kHz: **10.667 ms steps, 82.5 % of frames unchanged**; even the 128-sample floor (2.667 ms ≈ 375 Hz) is below a 600 Hz frame — and FREEZES entirely while the context is suspended (pre-autoplay-gesture). Every impact/interval constant is `*_ms`, every stamp `now_ms`. `prev_ms` = prior frame's `now_ms`; tracking modes use it as the start stamp `s` for `state.stats.shoots`
- **GC avoidance**: from `init()` to `dispose()` the per-frame hot path allocates nothing. Queue entries (`shoots`/`impacts`/`impacts_3d`) and per-mode targets come from `pool.js` free-lists — push `obtain()`s + fill every field, drop site `recycle()`s before `drop()`, `dispose()` `clear()`s the pools. `convert_target_*` write into a passed `out`. Per-mode details in `game_mode/CLAUDE.md`

## Hot paths
- **Start**: `controller/menu.js` → `logic.start_game(mode)` → lock + fullscreen (`await`ed FIRST, nothing below runs on failure) → sets `state.game.mode` + zeroes `input.ads_stage` → `game_sens.sync_game_resolution()` (card resolution ← real screen) → `mode.init()` → first rAF
- **Frame**: `logic.on_frame()` → space-hold gate → timer update (`now_ms` from rAF only; NO audio-clock read) → `mode.on_frame()` → if `now_ms >= state.hud.next_update_ms`: `check_stats?()` + `update_hud()` → toggle `#canvas-3d` display on `dimension` crossing `2d` → `mode.render()` → next rAF
- **Resize**: `controller/window.js:on_resize()` → `resize_2d()` (new `camera.width`/`height`) → `update_camera_projection()` → `resize_3d()` → `resize_bg()` — order is load-bearing
- **Dimension flip** (RMB down/up, `mousecancel`): `mode.update_dimension()` → `update_camera_view()` → `convert_camera_to_2d/3d` if camera state non-zero → `convert_target_to_2d/3d` → convert in-flight lerp endpoints

- `camera.fov_axis`/`view_fov` — what the branch chose, in the game's OWN declared units; the ONLY aspect-INDEPENDENT fov state. `camera.fov` (horizontal at the real aspect, paired with `width` for `sens`) and `camera.vfov` (vertical at the current aspect) are **DERIVED — recomputed on every view change AND every resize; never read either as stable across aspects**. `camera.dist` — TPP orbit offset (`constants.tpp.<game>` × `render_dist_scale`), zeroed at the top of `update_camera_view()`, set only by tpp branches. `proj`/`view` mutated in place by `prepare_3d_view()`
- `camera.sens_error` — `sens / calc_rad_per_px(fov, width) - 1`, written beside `sens`, consumed ONLY by the HUD's third top-right line. Every deliberate departure from monitor-matched-at-this-view in one number: usually `sens_scale - 1` (card rounding, ±0.5 %), but `bdo`/`sa` add their hipfire lock and SA its forced TRG multipliers (15× ≈ +112 %), and `cs2`/`rb`/`val` add the `ads_ref` gap on every scope their one typed field was not matched to (`rb` Minigun +13.38 % @16:9, +45 % @21:9, −12 % @5:4). **That gap moves with the ASPECT, not the resolution** — see `calc/CLAUDE.md`. MOVES on RMB — `calc_sens_snap` is view-dependent. Not a bug signal; never "fix" it toward 0
- `stats`: modes push to `shoots`; `check_stats()` expires entries and decrements aggregates. Exception: `aim_booster` pushes to its own module-local `shoots`
- `impact.rad_size` derived by `update_camera_projection()`, reset by 3D-capable mode `dispose()`; the 2D impact radius reads `constants.impact.px_size` directly
- `audio` = `{ bgm_volume, sfx_volume }` (0–100, scaled by `constants.audio.*_max_gain`). `bg` = `{ blur, type, video_id, youtube_link }` — `blur` toggles `body[bg-blur]`, uploaded blobs live in IndexedDB
- Mode-private state (`best_score`, peak/targets/lerps/timers) lives in `game_mode/<name>.js` module-locals, keyed `<module>#<field>` in localStorage

## create_queue (state.js)
Logical-head ring. `.length`, `.at(i)`, `.push()`, `.drop()`, `.clear()` respect the head. `.array` is the RAW backing buffer (head-dropped entries still present) — use it only when passing to a worker TOGETHER WITH the head offset (`lines_start = array.length - length`; a structured-cloned plain Array knows nothing about the head), or for `aim_booster`'s `.array.length =` rewind truncation. Compacts IN PLACE (`copyWithin`, no allocation) when `head > 2048` AND `head > q.length / 2` (half the RAW backing array, not the logical `.length`) — keeps the backing linear so `.array` stays valid, without a periodic `slice` spike.

Entry objects are pooled OUTSIDE the queue (`pool.js`): push a pooled object, `recycle()` at the drop site.
